## Usage

```ts
import { ResponsiveDatePicker } from "@voila.dev/ui/responsive-date-picker";
```

One declaration, two surfaces: the [DatePicker](/ui/date-picker) popover above
768px and the [NativeDatePicker](/ui/native-date-picker) below it, where the
wheel iOS and Android put up beats any calendar we could draw on a phone.
Narrow the window on the preview to watch it switch. The selection lives on the
`Root`, so crossing the breakpoint mid-form keeps the date.

The value is a `Date`, and `null` means empty — the same contract as
`DatePicker.Root`, which this takes its props from.

`min` and `max` bound both surfaces at once: they become the native field's
`min`/`max` attributes and, on desktop, the range of the year dropdown plus the
disabled days around it. The calendar always carries month and year dropdowns
here — a birth date is unreachable by paging a month at a time.

Without `min`/`max` the year dropdown still spans a century back and ten years
forward, so nothing is out of reach. (react-day-picker's own fallback stops at
the end of the current year, which hides every future date.)

There is no `Range` part: no browser ships a native range input, so a date range
stays on [`DatePicker.Range`](/ui/date-picker) on both surfaces.
