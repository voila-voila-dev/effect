**Your whole brand in one CSS file. Change it, everything follows.**

Every colour, radius and font in the system is a CSS custom property in the
OKLch colour space, in a single stylesheet. No JavaScript, no build step, no
theming API. That makes the tokens the contract between you and the
components: they only ever reference the semantic names, so redefining a
handful of properties rebrands buttons, tables, charts, the email editor and
the marketing sections at once. It also makes them the contract between you
and your AI: tell it to use `--primary` and there is nothing to hallucinate
around, because the whole theme is one readable file.

## Install

You rarely install it directly: `@voila.dev/ui` depends on it and its
`globals.css` imports it for you. Install it on its own when you want the
palette without the components.

```sh
bun add @voila.dev/ui
```

```css title="globals.css"
@import "tailwindcss";
@import "@voila.dev/ui/styles/themes/default.css";
```

Or copy the source — it's the same files. A theme is a composition of token
files (`styles/tokens/colors.css`, `typography.css`, `animations.css`), and it
reads as well in your repo as in `node_modules`.

Peers: `tailwindcss@4`.

## The 3-minute win

Rebrand the default palette. Redefine the properties you care about *after*
the import, in both themes:

```css title="globals.css"
@import "tailwindcss";
@import "@voila.dev/ui/styles/themes/default.css";

:root {
	--primary: oklch(0.55 0.21 145);       /* your brand green */
	--primary-foreground: oklch(0.99 0 0);
	--ring: oklch(0.55 0.21 145);          /* focus rings follow */
	--radius: 0.25rem;                     /* sharper corners */
}

.dark {
	--primary: oklch(0.72 0.18 145);       /* lighter, so it holds up on dark */
	--primary-foreground: oklch(0.16 0.01 145);
}
```

Every component that renders `bg-primary`, `ring` or a rounded corner now
follows your brand. No component is forked, no class is overridden.

## Mental model

The tokens are roles, not colours. Each role is a `color` plus `-foreground`
pair: the surface, and the text that goes on it. `--primary` is "the brand
action", `--muted-foreground` is "secondary text", `--destructive` is "this
deletes something". Components ask for roles through Tailwind's semantic
classes (`bg-primary`, `text-muted-foreground`, `border-border`) and never
name a raw colour, which is why one file can move the whole system. The one
rule that follows: override tokens, never component classes.
