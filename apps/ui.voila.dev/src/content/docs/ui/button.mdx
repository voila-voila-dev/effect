## Usage

```ts
import { Button } from "@voila.dev/ui/components/button";
```

```tsx
<Button variant="outline">Save</Button>
```

`Button` wraps [Base UI's button](https://base-ui.com/react/components/button),
so keyboard behaviour, focus management and the disabled semantics come from
there. What this component adds is the variant system, the size scale, and a
`loading` state that does the right thing for screen readers.

## Recipes

<Preview layout="row" label="Confirm a destructive action">
	<Example.ConfirmDestructive />
</Preview>

`destructive` is deliberately a tinted fill rather than a solid red block: a red
wall in a dialog footer reads as an error message, not a button. Pair it with an
`outline` cancel so the safe way out has weight too.

<Preview layout="row" label="Save while the request is in flight">
	<Example.Loading />
</Preview>

`loading` does three things at once: renders a leading `Spinner`, sets
`disabled`, and sets `aria-busy`. That last one is why you should prefer it over
rolling your own. Keep the label meaningful while it spins: "Saving…" tells the
user what is happening; a bare spinner does not.

<Preview layout="row" label="An icon-only toolbar action">
	<Example.IconSizes />
</Preview>

An icon-only button has no accessible name of its own. **Always pass
`aria-label`**. Icons are auto-sized here and alongside text; you never set
`size-4` yourself.

<Preview layout="row" label="Navigation that reads as a button">
	<Example.AsAnchor />
</Preview>

Base UI's `render` prop swaps the underlying element while keeping the styling
and behaviour:

```tsx
<Button render={<Link to="/missions/$id" params={{ id }} />}>Open mission</Button>
```

## API

| Prop | Default | |
| --- | --- | --- |
| `variant` | `"default"` | `secondary`, `outline`, `ghost`, `destructive`, `link`, plus the surface variants `provider` and `organization`. |
| `size` | `"default"` | `xs`, `sm`, `lg`, and the square `icon-*` set. |
| `shape` | `"default"` | `pill` forces a fully rounded button. |
| `loading` | `false` | Leading spinner, `disabled`, `aria-busy`. |
| `render` | — | Base UI: render as another element. |

All remaining props go to the underlying element. Picking a variant: `default`
is the one action the page exists for, at most one per view; `secondary` an
equal-weight alternative; `outline` for toolbars and anything that repeats in a
row; `ghost` inside dense surfaces; `destructive` for what cannot be undone;
`link` for an action that reads as navigation.

The variant and size names are also exported as arrays
(`buttonVariantOptions`, `buttonSizeOptions`), and the `cva` itself as
`buttonVariants` in `@voila.dev/ui/button-variants` if you need the classes
without the component.

Every state is in the
[Storybook story](https://storybook.ui.voila.dev/?path=/story/button).

## Own it

The source is `@voila.dev/ui/src/components/button.tsx`. To change the
variants, edit the cva block. It is the same file whether you keep the package
or copy it into your repo.

Reach for `className` for layout (`w-full`, `mt-2`), not for colour. If a
button needs a colour the variants do not have, the token behind the variant is
what should change; see [Theming](/start/theming/#the-one-rule).
