## Usage

```ts
import { Badge } from "@voila.dev/ui/components/badge";
```

```tsx
<Badge variant="destructive">Failed</Badge>
```

`Badge` covers two jobs that look the same and are not: labelling **status**
(pending, failed, verified) and labelling **category** (a tag, a skill, a
department). The first is semantic and uses `variant`; the second is arbitrary
and uses `color`.

## Recipes

<Preview layout="row" label="Status, where the colour means something">
	<Example.Variants />
</Preview>

`default` is neutral emphasis, `secondary` quieter metadata, `outline` the
quietest of all, `destructive` something failed or expired, `ghost` and `link`
the interactive chips.

<Preview layout="row" label="Category chips coloured from data">
	<Example.Colors />
</Preview>

Twenty fixed names, each with a `--badge-*` token and a dark override so chips
stay legible in both themes. Use them when the colour is a property of the
thing being labelled and it came out of a database:

```tsx
<Badge color={skill.color}>{skill.name}</Badge>
```

The set is deliberately closed: storing `"emerald"` in your data and mapping it
to a token means a chip renders the same everywhere. `color` wins over
`variant` if you pass both. The names are exported as `badgeColors` with the
`BadgeColor` type.

<Preview layout="row" label="A badge that navigates">
	<Example.AsLink />
</Preview>

Solid variants only hover when rendered as an anchor, so the chips that *are*
clickable are distinguishable. For a chip the user can remove, reach for
[Chip](/ui/chip) instead; it has the dismiss affordance built in.

## API

| Prop | Default | |
| --- | --- | --- |
| `variant` | `"default"` | `secondary`, `outline`, `destructive`, `ghost`, `link`, plus `brand` and `highlight`. |
| `color` | — | Catalogue palette; overrides `variant`. |
| `size` | `"default"` | `sm` for dense surfaces such as table cells. Below that, use text. |
| `render` | — | Base UI: render as another element. |

Colour alone is not an accessible status indicator; the label inside the badge
is doing the work and the colour is reinforcement. Never ship a badge whose
only content is a colour.

Every state is in the
[Storybook story](https://storybook.ui.voila.dev/?path=/story/badge).

## Own it

The source is `@voila.dev/ui/src/components/badge.tsx`. To change the palette
or the variants, edit the cva block and the `--badge-*` tokens next to it. It
is the same file whether you keep the package or copy it into your repo.
