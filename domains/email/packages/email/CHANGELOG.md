# @voila.dev/email

## 0.1.0

### Minor Changes

- 02f1808: `@voila.dev/email` becomes a domain with three subdomains on a shared vocabulary. Sending is the `EmailSender` contract, as before. Delivery is an outbox and a log: `SendEmailUseCase` writes the message first and attempts it inline, a refused attempt is retried on a curve up to 8 attempts, and `ProcessEmailOutboxUseCase` drains the retries, transactional mail first. `RecordEmailDeliveryEventUseCase` amends the log from provider webhooks, the worst outcome winning. Suppression is a list fed by hard bounces, complaints and repeated soft bounces, which every send checks, with use cases to block, release and search addresses. The use cases gate on the domain's own `EmailOperator` permissions and `EmailSystem`. `EmailLogRepository` and `SuppressionList` are contracts, with in-memory adapters. The existing exports are unchanged.
- 5480693: An `inbound` subdomain for received mail. `RecordInboundEmailUseCase` stores a message once, with its body, headers and SPF, DKIM and DMARC verdicts fetched through the `InboundEmailFetcher` contract. `RouteInboundEmailUseCase` rejects machine mail first (auto-reply and list headers, daemon senders, the application's own domains), then verifies the reply address and falls back to the send the reply quotes in `In-Reply-To`, and hands the payload to the application's `InboundEmailHandler`. `signedReplyAddresses` mints and verifies reply addresses signed with `@voila.dev/crypto`. `FetchInboundAttachmentUseCase` hands over a file only when the attachment policy allows it. `GetInboundEmailUseCase` and `SearchInboundEmailsUseCase` gate on the new `email.inbound.read` permission. `EmailLogRepository` gains `findByRfcMessageId`.
- 2ec8c99: First release. `@voila.dev/email`: the `EmailSender` contract every mail provider implements, the `EmailMessage` it takes, `EmailSendError`, and an in-memory and a console sender. `@voila.dev/resend`: an `EmailSender` on Resend (5 requests in flight, 429s retried with backoff and nothing else, batches of 100, messages with attachments sent on their own), the receiving API (body, SPF/DKIM/DMARC verdicts, attachments through the signed URL), the webhook event schema, and an in-memory receiving fake.
